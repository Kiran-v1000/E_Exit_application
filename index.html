End-to-end exit workflow
Sequential stages from resignation to final settlement
1
Resignation initiation
Employee submits an online resignation form with exit reason, preferred last working date, and optional note. System auto-calculates the policy-based last working date using notice period rules. Employee or manager can initiate; absconding cases handled separately.
EmployeeManager (on behalf)
2
Multi-level approval
Resignation routes through configurable approval chain: Reporting Manager → BU Head (optional) → HR. Each approver gets email + in-app notification with SLA timer. On rejection, employee is notified with reason and can appeal or resubmit. Withdrawal window configurable by policy.
Reporting ManagerHR
3
Knowledge transfer tasks
Upon approval, manager assigns KT tasks (documents, handover sessions, codebase walkthroughs) to the employee with deadlines. Employee uploads artifacts and marks tasks done. Manager confirms completion. System blocks F&F until KT is signed off.
ManagerEmployee
4
Department clearances
Parallel clearance requests sent to all departments simultaneously: IT (access revocation, device return), Admin (ID card, parking, desk), Finance (expenses, loans, advances), Projects (handover sign-off), Library (assets). Each HOD marks cleared or flags pending. Dashboard shows real-time status.
IT HODAdmin HODFinance HODProjects HOD
5
Exit interview & survey
HR schedules exit interview (online or in-person). Anonymous survey covers: work culture, manager relationship, compensation, growth, work-life balance. Survey responses visible only to HR leadership — never to reporting manager. Triggers sentiment analytics in the attrition dashboard.
HREmployee
6
Full & final settlement
After all clearances are green, Finance calculates F&F: pending salary (pro-rated), leave encashment, gratuity, deductions (notice shortfall, pending loans, unreturned assets), variable pay per policy. Finance approves, HR countersigns. Payment released on settlement date.
FinanceHR
7
Document generation & offboarding
Auto-generated PDFs: Resignation acceptance, Experience certificate, Relieving letter, NOC, F&F statement. Employee portal shows all documents for download. HR tags employee rehire eligibility. IT deactivates accounts. Exit status archived in system with full audit trail.
System (auto)HREmployee (download)

BullMQ job queues
Async jobs that run in the background via Redis
email-queue
Sends all email notifications — approval requests, SLA breach alerts, F&F ready, document generated. Retries 3× on failure.
pdf-queue
Generates PDFs using Puppeteer (relieving letter, F&F statement, etc.). Uploads to S3. Updates exit_documents table on completion.
sla-queue
Scheduled cron job (every 30 min) checks approval and clearance SLA deadlines. Escalates and fires breach notifications.
access-revoke-queue
Scheduled to run on approved_lwd. Triggers webhook/API calls to IT systems (Active Directory, GitHub, Jira) to revoke access.
clearance-init-queue
When approval is granted, bulk-creates clearance_requests for all is_clearance_dept departments and fires initial notifications.

Notice period calculation utility
// utils/noticePeriod.ts
function calcPolicyLWD(
  resignationDate: Date,
  employmentType: EmploymentType,
  policies: NoticePolicies
): Date {
  const days = policies[employmentType]; // e.g. confirmed = 60
  return addWorkingDays(resignationDate, days);
}

function calcFnFDeduction(
  approvedLWD: Date,
  actualLWD: Date,
  dailyRate: number
): number {
  const daysShort = diffWorkingDays(actualLWD, approvedLWD);
  return Math.max(0, daysShort) * dailyRate;
}
